## This stage: the hero domain and its data

The hero domain is generated by the slice generator from the approved spec, `specs/hero.json`. Do not hand-write it, and do not copy, edit or replace the spec. Run exactly:

`npx ng g slice --spec specs/hero.json --kinds entity`

It writes the domain under `src/app/hero/`:

- `hero.model.ts`: the `Hero` interface with the fields the spec lists, and one type per enum field.
- `hero.schema.ts`: the zod schema for the hero edit form, `heroSchema`, with the field labels on `.meta()`, and `export type HeroFormModel = z.infer<typeof heroSchema>`.
- `hero.service.ts`: `HeroService`, provided in root, holding the example roster as in-memory signal state, with `byId` for lookup by id and `update` as the update path, plus `create` and `remove`. There is no backend.
- `hero-example-data.ts`: the example roster from the spec, marked as example data.
- `hero.service.spec.ts`: the service's tests.

Every TypeScript file it writes starts with the generator's `@generated` header line. Leave the files where the generator put them and keep their names and exports: do not move them, rename them, or write a second model, schema or service beside them. Every later stage imports the domain from `src/app/hero/`. If a generated file needs a small addition, edit it in place.

Do not build any screen in this stage.
